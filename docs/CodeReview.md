# Code review guide

This guide collects the review rules that come up most often on pull requests in this repository. It is written for both human reviewers and AI reviewers, and for authors who want to self-review before asking for a review. The rules were distilled from maintainer review comments on public `rippled` pull requests; each rule links to one or more example comments.

It complements, and does not replace, [CONTRIBUTING.md](../CONTRIBUTING.md) (process, contracts, tests, style guide) and [docs/CodingStyle.md](./CodingStyle.md) (formatting). Where a rule overlaps those documents, it links to the relevant section.

## How to use

- Apply the **Correctness** rules first. Ignoring one risks wrong ledger state, a wrong result, a security issue, or a bug reaching a release.
- Then apply the **Style and conventions** rules.
- Cite the rule number in a review comment, e.g. "CR-17", so the author can find the rule and its examples.
- Rules are numbered continuously through the document so that a number is stable and citable; the headings only group them by theme.
- A rule is a default, not a law: if a change deliberately departs from one, the PR should say why.

## Correctness

### Amendments and feature gating

- **CR-1.** Amendment-gate every transaction-processing change that can alter ledger state or results, including removed checks, metadata changes, reordered fallible steps, and key-validity rules. See also [CONTRIBUTING.md](../CONTRIBUTING.md#before-making-a-pull-request) (amendment requirement). — [#7983](https://github.com/XRPLF/rippled/pull/7983#discussion_r3817618032) [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2393203810) [#5530](https://github.com/XRPLF/rippled/pull/5530#issuecomment-3058331919)
- **CR-2.** Skip amendment gating for changes that cannot alter the ledger: open-ledger relay or retry, RPC parsing, peer protocol, tem-code swaps, local consensus heuristics, reads of new fields, never-valid flags. — [#4985](https://github.com/XRPLF/rippled/pull/4985#discussion_r2064044058) [#8017](https://github.com/XRPLF/rippled/pull/8017#discussion_r3817808984) [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1920606304)
- **CR-3.** Do not add a new amendment for behaviour reachable only through an unreleased amendment; gate on it, add a fix amendment once it ships, and gate backports on the original. — [#5877](https://github.com/XRPLF/rippled/pull/5877#discussion_r2453640727) [#6113](https://github.com/XRPLF/rippled/pull/6113#discussion_r2608414379)
- **CR-4.** Respect amendment state until formal retirement: always check it as if disabled, preserve pre-amendment behaviour even when wrong, honour pre-amendment objects, and when retiring remove only the gating path. — [#6381](https://github.com/XRPLF/rippled/pull/6381#discussion_r2914804447) [#5650](https://github.com/XRPLF/rippled/pull/5650#discussion_r2294615413) [#6815](https://github.com/XRPLF/rippled/pull/6815#discussion_r3081221668)
- **CR-5.** Gate a transaction's existence in transactions.macro on the single amendment that introduced it; check prerequisites and new features of existing transactions via checkExtraFeatures. — [#5650](https://github.com/XRPLF/rippled/pull/5650#discussion_r2294750670) [#6338](https://github.com/XRPLF/rippled/pull/6338#discussion_r2818712504)
- **CR-6.** Gate a new invariant's failure on the amendment it enforces, but always run the check and log or XRPL_ASSERT(enforce) so violations surface even while disabled. — [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1932818675) [#5590](https://github.com/XRPLF/rippled/pull/5590#discussion_r2320285158) [#5877](https://github.com/XRPLF/rippled/pull/5877#discussion_r2453651659)
- **CR-7.** Never enable an amendment with known bugs or revert a shipped one (use Obsolete); keep fix amendments fix-only, drop superseded unreleased entries, and skip backports of unenabled fixes. — [#5444](https://github.com/XRPLF/rippled/pull/5444#issuecomment-3348215800) [#5550](https://github.com/XRPLF/rippled/pull/5550#discussion_r2219870131) [#6446](https://github.com/XRPLF/rippled/pull/6446#discussion_r3463776402)
- **CR-8.** Skip an amendment gate for a new branch only when every production caller provably yields the identical outcome, and document that proof in a comment. — [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2553643528) [#5650](https://github.com/XRPLF/rippled/pull/5650#discussion_r2301732767)

### Transactor structure and result codes

- **CR-9.** Put checks needing only transaction fields and Rules in preflight (tem codes); ledger-dependent or mutating checks go in preclaim or doApply; run universal preflight checks before transactor-specific ones. — [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1844620179) [#5354](https://github.com/XRPLF/rippled/pull/5354#discussion_r2010888968) [#5650](https://github.com/XRPLF/rippled/pull/5650#discussion_r2294652160)
- **CR-10.** Never throw on transaction data; return tecINTERNAL or tefINTERNAL for conditions earlier steps made impossible, keep logicError in destructors and consensus paths, and catch every throwing call. — [#6446](https://github.com/XRPLF/rippled/pull/6446#discussion_r3471187820) [#5652](https://github.com/XRPLF/rippled/pull/5652#discussion_r2285932675)
- **CR-11.** Return the result code that describes the actual failure, propagate a helper's TER unchanged, tolerate only the specific expected error, and never let cleanup failures override the primary result. — [#5652](https://github.com/XRPLF/rippled/pull/5652#discussion_r2288255721) [#5224](https://github.com/XRPLF/rippled/pull/5224#discussion_r1931389839) [#5863](https://github.com/XRPLF/rippled/pull/5863#discussion_r2453585694)
- **CR-12.** Keep every transactor check and result code in sync with the XLS spec; when the spec omits a protocol invariant or is wrong, fix the spec rather than silently diverging. — [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2326189564) [#6361](https://github.com/XRPLF/rippled/pull/6361#discussion_r2849902387) [#6133](https://github.com/XRPLF/rippled/pull/6133#discussion_r2625218980)
- **CR-13.** Route freeze checks through the central isFrozen/isDeepFrozen/checkFrozen helpers; senders must not be frozen, receivers not deep-frozen, and FreezeHandling::IgnoreFreeze must bypass both freeze types. — [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1844651772) [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2553777619) [#6113](https://github.com/XRPLF/rippled/pull/6113#pullrequestreview-3633210315)
- **CR-14.** Reject invalid input strictly: throw at startup for bad config or inconsistent static tables, treat unparseable RPC parameters as malformed; a wrong answer is worse than an error. — [#5468](https://github.com/XRPLF/rippled/pull/5468#discussion_r2263482174) [#6613](https://github.com/XRPLF/rippled/pull/6613#discussion_r3203986794) [#5317](https://github.com/XRPLF/rippled/pull/5317#discussion_r1970212029)
- **CR-15.** Enforce transaction rules in the Transactor, never in STParsedJSON (peers and tx_blob bypass JSON), and derive per-type tables from one source: getPseudoAccountFields, a single struct map, exhaustive tests, collision asserts. — [#5354](https://github.com/XRPLF/rippled/pull/5354#discussion_r2003698141) [#5590](https://github.com/XRPLF/rippled/pull/5590#discussion_r2286599029) [#6613](https://github.com/XRPLF/rippled/pull/6613#discussion_r3203545614)
- **CR-16.** Validate amounts asset-agnostically through isLegalNet/isLegalMPT (hasInvalidAmount), rejecting negative MPT amounts, and name predicates by what they actually check. — [#7117](https://github.com/XRPLF/rippled/pull/7117#discussion_r3222696826)
- **CR-17.** Treat the issuer specially: creating its own trust line or MPToken is a no-op success, transfer checks short-circuit for the issuer, and rippling blocks only if both lines set NoRipple. — [#6017](https://github.com/XRPLF/rippled/pull/6017#discussion_r2512277735) [#5877](https://github.com/XRPLF/rippled/pull/5877#issuecomment-3434719985) [#5875](https://github.com/XRPLF/rippled/pull/5875#discussion_r2424948870)
- **CR-18.** Default ledger arithmetic to round-to-nearest unless the spec or an exploit dictates otherwise, multiply before dividing, round to asset precision before storing, and correct intrinsic drift rather than failing. — [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2356903452) [#6037](https://github.com/XRPLF/rippled/pull/6037#discussion_r2538947268)
- **CR-19.** Reuse Transactor::checkSign, Transactor::getFeePayer or STTx::getFeePayerID and STTx signature verification instead of re-implementing signing rules inline, so implementations cannot drift. — [#6446](https://github.com/XRPLF/rippled/pull/6446#discussion_r3484519505) [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2386406453)
- **CR-20.** When behaviour depends on the submitter's role, validate per role, handle one account holding both roles, and define the zero-amount or nothing-to-act-on case. — [#6120](https://github.com/XRPLF/rippled/pull/6120#discussion_r2625014963)
- **CR-21.** Before creating a trust line on an account's behalf, check in preclaim that the issuer exists and has lsfDefaultRipple so a default-state line is never created. — [#5224](https://github.com/XRPLF/rippled/pull/5224#discussion_r1932973682)
- **CR-22.** When an amendment adds flag validation, fail previously ignored invalid combinations with a tec code, and validate them even when the trust line does not yet exist. — [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1868484669)
- **CR-23.** Obtain the transaction's SeqProxy once via getSeqProxy(), never from tx[sfSequence]; sequence numbers and tickets are the replay protection, not open-view transaction lookups. — [#7890](https://github.com/XRPLF/rippled/pull/7890#discussion_r3669146462) [#6446](https://github.com/XRPLF/rippled/pull/6446#discussion_r3471101599)
- **CR-24.** Use a fallback fee in calculateBaseFee only when every failure condition is independently rejected in preflight; let unexpected exceptions propagate rather than validating an underpaid transaction. — [#7736](https://github.com/XRPLF/rippled/pull/7736#discussion_r3583066724)
- **CR-25.** When computing per-account balance deltas, attribute the fee to the fee payer (sfDelegate when present, else sfAccount) and handle fees exceeding the amount moved. — [#5876](https://github.com/XRPLF/rippled/pull/5876#discussion_r2440443748) [#6434](https://github.com/XRPLF/rippled/pull/6434#discussion_r2862050948)
- **CR-26.** Reserve checks must use the balance before fees (Transactor::preFeeBalance\_) and reuse SetTrust's reserve rule whenever a transaction may create a trust line. — [#5176](https://github.com/XRPLF/rippled/pull/5176#discussion_r1828164322)
- **CR-27.** Create pseudo-accounts with Sequence 0 and initialise new ledger-object sequence counters to 1; XRPL sequences are read-then-incremented and 0 is invalid. — [#5224](https://github.com/XRPLF/rippled/pull/5224#discussion_r2008429190) [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2551224765)
- **CR-28.** Reject sentinel AccountIDs (xrpAccount, noAccount) where accounts are created (e.g. Payment destination), amendment-gated, rather than in every downstream consumer. — [#7098](https://github.com/XRPLF/rippled/pull/7098#discussion_r3237896909)
- **CR-29.** When fixing a validation gap for a field in one transactor, apply the same check and tests to every transactor that uses that field. — [#5967](https://github.com/XRPLF/rippled/pull/5967#pullrequestreview-3402294437) [#5977](https://github.com/XRPLF/rippled/pull/5977#pullrequestreview-3412817813)

### Ledger objects, fields and flags

- **CR-30.** Choose SoeDefault when zero is natural; use SoeOptional when absence must differ from zero on pre-amendment objects or the field is populated during signing, enforcing presence in preflight. — [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2386410363) [#6564](https://github.com/XRPLF/rippled/pull/6564#issuecomment-4433542924) [#8016](https://github.com/XRPLF/rippled/pull/8016#discussion_r3817219097)
- **CR-31.** Reject flags from a disabled amendment with temINVALID_FLAG in preflight via an amendment-suffixed mask selected in getFlagsMask, never by hand-written checks or duplicated flag lists. — [#6361](https://github.com/XRPLF/rippled/pull/6361#discussion_r2830357650) [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1844697209) [#5592](https://github.com/XRPLF/rippled/pull/5592#issuecomment-3251181498)
- **CR-32.** Read transaction flags with tx.getFlags() (sfFlags is optional), mask out tfUniversal before exclusivity tests, and use lsf* constants for ledger objects and tf* for transactions, never mixed. — [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2334608394) [#5652](https://github.com/XRPLF/rippled/pull/5652#discussion_r2302324013)
- **CR-33.** Null-check every SLE from view.read or peek before dereferencing and return tefBAD_LEDGER or tefINTERNAL with LCOV_EXCL_LINE, even when a null is nearly impossible. — [#7886](https://github.com/XRPLF/rippled/pull/7886#discussion_r3799843692) [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2558234275) [#6715](https://github.com/XRPLF/rippled/pull/6715#discussion_r3096935376)
- **CR-34.** Express which transaction types may touch a ledger object as named Privileges in transactions.macro checked via hasPrivilege; per-type switches must fail on unhandled types. — [#5518](https://github.com/XRPLF/rippled/pull/5518#discussion_r2383009008) [#5590](https://github.com/XRPLF/rippled/pull/5590#discussion_r2286508660)
- **CR-35.** When comparing rounded amounts, round both sides with the same scale derived from an STNumber exponent (zero values use the minimum exponent), and register Number-affecting amendments in createGuards. — [#6217](https://github.com/XRPLF/rippled/pull/6217#discussion_r2710177415) [#7051](https://github.com/XRPLF/rippled/pull/7051#discussion_r3228574015)
- **CR-36.** Do not weaken long-standing serialization rules: placeholder SFields stay signing fields, and assertions catching protocol-invalid state stay; fix the legacy callers instead. — [#7008](https://github.com/XRPLF/rippled/pull/7008#discussion_r3170007003) [#6267](https://github.com/XRPLF/rippled/pull/6267#discussion_r3640191726)
- **CR-37.** Call view.update(sle) once per modified SLE per transaction; its position among the modifications is irrelevant, but it must happen. — [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2389606850) [#6408](https://github.com/XRPLF/rippled/pull/6408#discussion_r2865782440)

### Invariants, asserts and defensive checks

- **CR-38.** For impossible branches write `if (cond) { UNREACHABLE(...); return error; }` with LCOV exclusion; a bare XRPL_ASSERT or a silent tefINTERNAL alone is insufficient. See also [CONTRIBUTING.md](../CONTRIBUTING.md#contracts-and-instrumentation). — [#5224](https://github.com/XRPLF/rippled/pull/5224#discussion_r1932980450) [#7354](https://github.com/XRPLF/rippled/pull/7354#discussion_r3325640961) [#7445](https://github.com/XRPLF/rippled/pull/7445#discussion_r3470744246)
- **CR-39.** Invariants must check every failure condition even when transactors make it impossible: collect all affected objects, fail on unexpected counts, encode field implications, guard malformed entries, run in one try/catch. — [#5518](https://github.com/XRPLF/rippled/pull/5518#discussion_r2389379668) [#6134](https://github.com/XRPLF/rippled/pull/6134#pullrequestreview-3569809158) [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1932830239)
- **CR-40.** In invariant visitEntry, `after` is never null: detect deletions only via isDelete, return early when deletes are irrelevant, and compare before/after for modifications. — [#7089](https://github.com/XRPLF/rippled/pull/7089#discussion_r3205215474) [#5518](https://github.com/XRPLF/rippled/pull/5518#discussion_r2389354074) [#7087](https://github.com/XRPLF/rippled/pull/7087#discussion_r3283241149)
- **CR-41.** Validate inputs inside shared helpers rather than trusting callers: assert an SLE is non-null and of the expected type, and check asset matches, slice sizes and range limits. — [#5143](https://github.com/XRPLF/rippled/pull/5143#discussion_r1817293373) [#6361](https://github.com/XRPLF/rippled/pull/6361#discussion_r2830628691) [#6715](https://github.com/XRPLF/rippled/pull/6715#discussion_r3095501906)
- **CR-42.** Where an XRPL_ASSERT violation would corrupt state, add a runtime guard with the identical condition; asserts are compiled out of release builds. — [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2389632726) [#5652](https://github.com/XRPLF/rippled/pull/5652#discussion_r2302399806)
- **CR-43.** Enforce constraints in transactors and helpers first and keep cheap redundant checks (prefer >= over == on limits) as defense in depth; invariants are the last line of defense. — [#5185](https://github.com/XRPLF/rippled/pull/5185#discussion_r2066921914) [#5875](https://github.com/XRPLF/rippled/pull/5875#discussion_r2461258409) [#6110](https://github.com/XRPLF/rippled/pull/6110#discussion_r2612527253)
- **CR-44.** Never let transaction or peer input reach an XRPL_ASSERT; validate it with a runtime check that returns an error, and drop asserts that merely duplicate such checks. — [#5143](https://github.com/XRPLF/rippled/pull/5143#discussion_r1817308992) [#6120](https://github.com/XRPLF/rippled/pull/6120#discussion_r2625059914) [#6446](https://github.com/XRPLF/rippled/pull/6446#discussion_r3484484069)
- **CR-45.** Invariants must hold when the transaction fails: never return true early on a non-tesSUCCESS result; instead verify no guarded objects were touched. — [#6134](https://github.com/XRPLF/rippled/pull/6134#discussion_r2641358394) [#6477](https://github.com/XRPLF/rippled/pull/6477#discussion_r2908054264)
- **CR-46.** Put a check you cannot make bulletproof, or one on internal values not visible in ledger state, in a debug-only XRPL_ASSERT rather than a consensus-affecting invariant. — [#6231](https://github.com/XRPLF/rippled/pull/6231#discussion_r2766375337)
- **CR-47.** Mark every function returning a TER [[nodiscard]] and never silence the result with [[maybe_unused]]; handle or at least log the failure. — [#6715](https://github.com/XRPLF/rippled/pull/6715#discussion_r3047662109)
- **CR-48.** Avoid C++ footguns: capture by value in lambdas that outlive the call, never cast a negative double to unsigned, and read atomic or mutable values once into a local. — [#5644](https://github.com/XRPLF/rippled/pull/5644#discussion_r2688120389) [#6476](https://github.com/XRPLF/rippled/pull/6476#discussion_r2914473797) [#5282](https://github.com/XRPLF/rippled/pull/5282#issuecomment-3416079070)
- **CR-49.** Represent not-yet-computed or not-found state with std::optional rather than an empty container or parallel present flags, so later accessors detect the unbuilt case. — [#6446](https://github.com/XRPLF/rippled/pull/6446#discussion_r3484452550) [#7029](https://github.com/XRPLF/rippled/pull/7029#discussion_r3456108306)
- **CR-50.** Assignment discards a vector's pre-sizing; assert a positionally indexed batch result is empty or exactly the request size before index-based access. — [#5439](https://github.com/XRPLF/rippled/pull/5439#discussion_r2760984777)

### Tests

- **CR-51.** Assert exact expected values from independently known literals or golden hashes, with distinct inputs and both returned and mutated results; never derive a test's expectation from the code under test. — [#6434](https://github.com/XRPLF/rippled/pull/6434#discussion_r2866608471) [#5143](https://github.com/XRPLF/rippled/pull/5143#discussion_r1815620170) [#5468](https://github.com/XRPLF/rippled/pull/5468#discussion_r2263410428)
- **CR-52.** After each transaction in a test, assert the resulting ledger state and balances in every branch, including absent objects, flags and transfer-fee effects, not just the result code. — [#5143](https://github.com/XRPLF/rippled/pull/5143#discussion_r1806992341) [#6108](https://github.com/XRPLF/rippled/pull/6108#discussion_r2608368033) [#5997](https://github.com/XRPLF/rippled/pull/5997#discussion_r2495065648)
- **CR-53.** Probe both sides of every numeric boundary in tests: limit and limit+1, numeric_limits min and max, amounts that round to zero, mixed mantissas, and the not-yet-due case. — [#5990](https://github.com/XRPLF/rippled/pull/5990#discussion_r2495109086) [#6434](https://github.com/XRPLF/rippled/pull/6434#discussion_r2866564439)
- **CR-54.** Cover every role, direction and asset type: holder-to-holder and back to issuer, issuer sending and receiving, XRP/IOU/MPT, each enum value, and sibling RPC commands sharing a parser. — [#5143](https://github.com/XRPLF/rippled/pull/5143#discussion_r1807085023) [#6113](https://github.com/XRPLF/rippled/pull/6113#discussion_r2608434704) [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1925541683)
- **CR-55.** Validate the tests themselves: confirm a regression test fails without the fix, question unexplained expectation changes, and check nothing silently disables a test or fails for the wrong reason. — [#5270](https://github.com/XRPLF/rippled/pull/5270#discussion_r2393271064) [#5670](https://github.com/XRPLF/rippled/pull/5670#discussion_r2302084434) [#6113](https://github.com/XRPLF/rippled/pull/6113#discussion_r2641453312)
- **CR-56.** Parameterize amendment-sensitive tests on a FeatureBitset actually passed to Env, run them with and without each new amendment (including all disabled), and rerun when defaults flip. — [#7050](https://github.com/XRPLF/rippled/pull/7050#discussion_r3169931675) [#6036](https://github.com/XRPLF/rippled/pull/6036#discussion_r2539476142) [#6069](https://github.com/XRPLF/rippled/pull/6069#discussion_r2621516482)
- **CR-57.** Never remove or rewrite an existing test scenario; update its expected outcome and add a new scenario for the new behaviour, keeping amendment-gated tests enabled. — [#5143](https://github.com/XRPLF/rippled/pull/5143#discussion_r1800285789) [#7117](https://github.com/XRPLF/rippled/pull/7117#discussion_r3288281620) [#6108](https://github.com/XRPLF/rippled/pull/6108#discussion_r2608226807)
- **CR-58.** Pair each new permissive path with negative tests for every unmet precondition and a positive test proving the condition under test was the only factor. — [#6120](https://github.com/XRPLF/rippled/pull/6120#discussion_r2625149058) [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1905866844) [#6053](https://github.com/XRPLF/rippled/pull/6053#discussion_r2542663538)
- **CR-59.** Add a unit test for every new branch or defensive check, including invariants exercised through create, modify and delete, legacy bad state, concurrency and exception paths. — [#7312](https://github.com/XRPLF/rippled/pull/7312#discussion_r3285102694) [#5276](https://github.com/XRPLF/rippled/pull/5276#discussion_r1953141557) [#5354](https://github.com/XRPLF/rippled/pull/5354#discussion_r2010773790)
- **CR-60.** Test both the omitted and explicit-zero form of a field, absent versus false in RPC output, default and explicit limits, and an optional field against a missing target. — [#5187](https://github.com/XRPLF/rippled/pull/5187#discussion_r1926146987) [#5967](https://github.com/XRPLF/rippled/pull/5967#discussion_r2475015678) [#6119](https://github.com/XRPLF/rippled/pull/6119#discussion_r2624947310)
- **CR-61.** In tests expecting an exception, put fail() right after the throwing call and assert the caught exception's what() with BEAST_EXPECTS. — [#5172](https://github.com/XRPLF/rippled/pull/5172#discussion_r1828320137) [#5112](https://github.com/XRPLF/rippled/pull/5112#discussion_r1913939705)

### Concurrency and locking

- **CR-62.** Give functions that must run under a mutex an unnamed const lock parameter proving it is held; avoid recursive mutexes, shared-to-unique upgrades, and exposing a guarded wrapper's lock. — [#6447](https://github.com/XRPLF/rippled/pull/6447#discussion_r2880939260) [#4985](https://github.com/XRPLF/rippled/pull/4985#discussion_r1841334087) [#5276](https://github.com/XRPLF/rippled/pull/5276#discussion_r1945183973)
- **CR-63.** Never allocate or copy large containers while holding a lock; reserve outside the lock, re-check under it, or hand out shared_ptr snapshots. — [#7567](https://github.com/XRPLF/rippled/pull/7567#discussion_r3582093861) [#8240](https://github.com/XRPLF/rippled/pull/8240#discussion_r4189885137) [#8540](https://github.com/XRPLF/rippled/pull/8540#discussion_r4252532717)
- **CR-64.** Keep read-modify of cache-shared objects under the owning lock: never mutate a canonicalized entry outside the cache lock, and give the owner its own mutex when removing a shared one. — [#5874](https://github.com/XRPLF/rippled/pull/5874#discussion_r2862063502)

### Peer protocol and networking

- **CR-65.** Gate peer-protocol behaviour changes on a new ProtocolVersion, keeping old behaviour for older peers. — [#6110](https://github.com/XRPLF/rippled/pull/6110#discussion_r2714233863)
